# HTML实现与验收要点

## 离线打包

使用单一内容数据源生成网页，生成脚本与内容稿另存。避免同时内嵌PDF数据和包含同一PDF数据的整份内容稿，否则文件会接近翻倍。Base64会增加体积，嵌入后需要对解码字节计算哈希，不能仅比较字符串长度。

只在实际需要时加入原书嵌入、图表、计算器、考试或账户功能。不要复制与当前书无关的旧书题目、卡片数量、页数、专名和投资假设。

内嵌原书使用Blob URL定位到PDF文件页序，提供保存原书副本按钮作为阅读器兼容后备；未实际验证跳页时说明限制。独立PDF方案则一并打包相对路径文件，明确HTML不能单独移动。

本地内容不能依赖CDN字体、外链JS、联网图片或从本地路径fetch才能加载的关键JSON。引用外站的阅读链接不属于加载依赖。通过用户认可的浏览器工具检查自动外部请求，不因“离线”一词就假定没有外部加载。

## 稳定的内容与状态

章节、方法、问题使用稳定ID，展示标题改变不应破坏记录关联。练习保存有版本标识；导出不包括隐式私密上下文。导入限制大小，验证字段与ID，失败时保持现有状态。备份文件包含用户文字，分享提醒应简洁。

源码中保留空白练习。下载可分享HTML应读取原始页面文件，不导出包含用户输入的实时DOM。本地文件不可fetch时直接提示复制原HTML；不将“另存为网页”与练习备份混为一谈。

## 布局与改版

默认布局与样式使用 [reading-desk.md](reading-desk.md) 及其资源。验收时重点检查搜索位于正文右上角、侧栏不重复书名、清空键遵守 `hidden`、窄屏搜索不打开目录，以及多层折叠内的深层定位。

先观察实际父子结构，例如：

```text
main
  hero
  layout
    aside
    article
      section...
```

此结构的双栏布局应设在`layout`，不能只把`main`设成两列，再给内层section设grid-column。正文列使用允许收缩的宽度并给容器设置min-width；窄屏将同一个布局容器切到单列。

不仅检查首页：用真实较长章节、展开详情、较长表单及URL深层锚点检查目录是否压住正文。小屏测试长中文、长链接、表格和选择框。根据已声明设计系统测文字对比度，但对比度检查不能替代视觉检查。

改版前后比较学习数据与主要交互脚本；需要改逻辑时说明具体变化并测试对应功能。仅视觉改版不要顺手改变书名、品牌名、内容结构或练习口径。

## 最小浏览器验收矩阵

| 场景 | 适用条件 | 观察结果 |
|---|---|---|
| 桌面与约390px窄屏 | 有网页 | 无正文／目录重叠、整页横向溢出；长书名省略且可访问名称完整，控件可读 |
| 首次加载与深层锚点 | 有网页；深层锚点按实际提供检查 | 正常初始化，定位到所需章节／方法 |
| 搜索有结果、无结果、清空 | 有搜索 | 章节标题、正文、独立概念可检索，父子不重复计数；清空恢复搜索前章节 |
| 移动目录及断点切换 | 有移动目录 | 打开后跨断点再返回，目录关闭、滚动恢复、`aria-expanded=false` |
| 切章 | 有多章节导航 | 内容与选择项相符 |
| 标记已读 | 有已读记录 | 刷新后记录保留 |
| 填练习、切换再回来 | 有练习 | 原文字保留；存储失败有清晰反馈 |
| 导出、有效导入、无效导入 | 有记录导入导出 | 数据可恢复；无效文件不破坏现有状态 |
| 自测部分题／错题复习 | 有自测；错题复习按实际提供检查 | 未答与答错区分，解析与来源可达 |
| 计算器 | 有计算器 | 代表例与边界结果正确，单位和假设可见 |
| 来源跳转／PDF保存 | 有来源入口；PDF保存按实际提供检查 | 正文来源可定位或有明确后备入口 |
| 控制台、加载资源 | 有网页 | 无脚本异常，无意外网络加载 |

未实现且不需要的功能记为“不适用”，不为填满矩阵而新增功能；需要但尚未实现或验证的功能不能记为“不适用”。

使用当前环境允许的工具；浏览器或网络访问被策略拦截时不绕过。截图、交互结果、静态结构三者分开描述。没有真实运行结果就标为未验证，交付说明中不要只说“校验通过”。
